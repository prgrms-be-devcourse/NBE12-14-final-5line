# TourAPI 초기 장소 수집

EC2에서 배포된 이미지와 서버 `.env`를 사용하려면 [EC2 초기 장소 데이터 반영 안내](ec2-initial-places.md)를 따른다.

## 실행 범위

명시적으로 선정한 500곳을 수집한다. 공식 시설 안내와 대조한 초기 5곳, 서울 중심·동부 45곳, 전국 레포츠 장소 450곳으로 구성한다. 전국 추가 대상은 TourAPI의 목록과 상세에서 이름, 주소, 좌표를 대조했다. 추가 450곳의 종목은 비워 둔다. [전체 수집 대상](../src/main/java/com/outpick/domain/place/importer/TourImportTarget.java)

| 콘텐츠 ID | 대상 | 초기 연결 종목 |
| --- | --- | --- |
| 2678888 | 시흥 웨이브파크 | 서핑 |
| 646762 | 곤지암리조트 스키장 | 스키, 스노보드 |
| 2727468 | 스카이라인 루지 부산 | 루지 |

이 연결은 검수 전 후보 정보다. 종목이 불명확한 시설은 분류와 종목을 비워 둔다. 실내외·시즌·현재 운영 상태는 응답이나 종목명으로 추정해 넣지 않는다.

## Make로 로컬 초기 장소 준비

프로젝트 루트 `.env`에 기존 MySQL 설정과 `TOUR_API_KEY=일반 인증키(Decoding)`를 저장한다. 키와 비밀번호를 Git에 올리지 않는다. Docker Desktop, Java 25, `node:util`의 `parseEnv`를 지원하는 Node.js, Make가 필요하다.

프로젝트 루트에서 실행한다.

```bash
make places-init
```

MySQL 준비가 완료될 때까지 기다리고, 현재 Backend 소스로 장소를 수집한다. 이어서 공개 SQL을 실행해 검수 조건을 충족한 초기 장소와 지도 검증용 전국 장소를 공개하고 결과를 조회한다. 중간 명령이 실패하면 다음 단계는 실행하지 않는다. 앞 단계에서 저장한 데이터는 유지되므로 실패 원인을 해결한 뒤 다시 실행한다.

이미 수집한 장소는 `SKIPPED`로 처리한다. 마지막 조회에서 `publish_status`가 `0`이면 초안, `1`이면 공개, `2`이면 숨김이다.

단계별로 실행할 때는 다음 명령을 사용한다.

| 명령 | 실행 내용 |
| --- | --- |
| `make compose-up` | 로컬 MySQL 실행 및 준비 완료 대기 |
| `make places-import` | 후보 500곳 중 수집 이력이 없는 장소를 공개 전 상태로 저장 |
| `make places-list` | 수집한 장소와 공개 상태 조회 |
| `make places-publish-initial` | 검수 조건을 충족한 초기 5곳과 지도 검증용 초안 최대 495곳 공개 |
| `make mysql-shell` | 로컬 MySQL에 접속, `exit`으로 종료 |

수집 명령은 `.env`에서 필요한 값을 읽어 Gradle `importTourPlaces`에 전달한다. Docker 이미지를 다시 빌드할 필요가 없다. 수집 대상 DB는 `127.0.0.1`과 `.env`의 `MYSQL_PORT`이며, 포트를 생략하면 `3306`이다. `.env`의 `MYSQL_HOST`는 이 명령에서 사용하지 않는다. 조회·공개·MySQL 접속은 개발용 `compose.yaml`의 MySQL을 사용한다. 개별 명령을 실행하기 전에는 `make compose-up`으로 MySQL을 준비한다.

`published_this_run`은 초기 검수 장소의 공개 건수다. `published_map_test_this_run`은 지도 검증용 장소의 공개 건수다. 로컬과 EC2 초기화 명령은 같은 공개 SQL을 실행한다. 이 SQL은 선정한 콘텐츠 ID의 TourAPI 수집 이력과 출처를 확인한 뒤 해당 초안의 게시 상태만 변경한다. 기존 50곳이 공개된 DB에서는 새 대상 450곳만 수집·공개한다. 같은 명령을 다시 실행하면 이미 공개한 장소는 두 건수에서 빠진다. [공개 SQL](../scripts/review-initial-tour-places.sql)

Backend와 Frontend 개발 서버는 평소처럼 별도로 실행한다. 공개 후 로컬 브라우저에서 장소 목록을 새로 조회해 표시 여부를 확인한다.

지도에서 50곳 제한을 확인하려면 필터를 해제하고 서울 중심·동부를 본다. 위도 37.48~37.60, 경도 126.92~127.16 범위에는 초기 대상 63곳이 있다. 위도 37.49~37.60, 경도 127.02~127.16의 서울 동부로 범위를 좁히면 26곳으로 줄어든다. 실제 지도 검색 범위는 브라우저 창 크기와 확대 수준에 따라 달라진다.

## 로컬 실행 (PowerShell)

프로젝트 루트 `.env`에 `TOUR_API_KEY=일반 인증키(Decoding)`와 기존 MySQL 설정을 둔다. `.env`는 Git에서 제외되며 프런트엔드 환경 변수에 키를 넣지 않는다. Java 25와 실행 중인 Docker Desktop이 필요하다.

```powershell
docker compose up -d --wait --wait-timeout 180
powershell -ExecutionPolicy Bypass -File ./backend/scripts/import-tourapi.ps1
```

스크립트는 필요한 환경 변수만 읽고 Gradle `importTourPlaces`를 실행한다. 명령은 `local` 설정을 사용하는 별도 프로세스로, 웹 서버를 열지 않고 종료한다. 기존 8080 서버와 병행 실행할 수 있다. 일반 `bootRun`/서버 시작 및 CI 테스트에서는 외부 API를 호출하지 않는다. `.env`의 DB 호스트·포트가 의도한 로컬 DB인지 확인한다.

결과는 콘텐츠 ID와 `CREATED`, `SKIPPED`, `FAILED`로 표시한다. 일부 실패는 다른 후보와 격리하며 하나라도 실패하면 종료 코드 1을 반환한다. 원본 응답·인증키·요청 URL·원인 예외는 결과 로그에 포함하지 않는다.

## 저장 규칙

- 공식 `KorService2/detailCommon2`만 호출한다. 인증키는 한 번 인코딩하고 HTTP 리다이렉트를 따르지 않는다. 연결 제한 5초, 요청 제한 15초, 응답 최대 2MiB다.
- HTTP 성공뿐 아니라 제공기관 결과 코드, 콘텐츠 ID, 레포츠 유형(28), 예상 시설명, 주소·좌표·필드 길이·원본 수정일을 확인한다. 잘못된 응답은 저장하지 않는다.
- 홈페이지의 HTML 링크와 일반 텍스트를 HTTP(S) URL로 정규화한다. 소개는 일반 텍스트로 저장한다. 이미지·운영시간·요금은 수집하지 않는다.
- 장소와 종목, 출처, 수집 이력을 **한 장소 단위 트랜잭션**으로 저장한다. 항상 `DRAFT(0)`이며 공개 검색·상세에서 제외된다.
- 출처의 `origin_updated_at`은 제공기관의 수정일이다. 수집 이력의 `collected_at`은 서울 시간의 수집일이다. 운영자 검수일인 `verified_at`/`reviewed_at`은 비워둔다.
- `tour_api_import.content_id` 기본 키로 재수집을 방지한다. 저장 구간의 DB 잠금으로 동시 실행도 한 번만 저장한다. HTTP 호출 동안 DB 잠금을 유지하지 않는다.
- 재실행은 기존 장소를 덮어쓰지 않고 `SKIPPED` 처리한다. 운영자가 수정·공개한 정보도 유지한다. API 실패는 기존 데이터에 영향을 주지 않는다.
- 기존 지역·분류·종목은 재사용하고 수정하지 않는다. 수집 이력 없이 이미 존재하는 시설이나 서로 다른 콘텐츠 ID 간의 동일 시설 여부는 사람이 확인해야 한다.

## 공개 전 확인

현재 DB에 저장됐다는 사실만으로 사이트에 공개하지 않는다. 시설·종목 매칭, 주소·좌표, 공식 링크 및 소개 이용 조건을 검토하고, 확인한 항목의 출처와 검수일을 기록한 뒤 기존 장소 운영 흐름에서 공개한다. 대표 사진은 별도의 선정·권리 확인 정책을 따른다.

V7 마이그레이션은 수집 이력/잠금 테이블을 추가한다. 기존 V1~V3 및 공용 출처 테이블을 수정하지 않는다. 실패한 콘텐츠는 원인을 해결한 뒤 같은 명령을 재실행할 수 있으며, 이미 성공한 콘텐츠는 건너뛴다.

제공 서비스: [한국관광공사 국문 관광정보 서비스_GW](https://www.data.go.kr/data/15101578/openapi.do)

## 2026-11-16 로컬 초기 공개

`scripts/review-initial-tour-places.sql`의 초기 검수 공개 구간은 이날 확인한 5곳에 당시 검수 내용을 반영한다. 일반 수집은 DRAFT로 저장하며, 공개 SQL은 로컬과 EC2에서 초기 장소 준비 명령을 실행할 때 적용한다.

- 웨이브파크: [공식 교통안내](https://www.wavepark.co.kr/trafficguide)로 도로명 주소를 대조했고, [공식 메인](https://www.wavepark.co.kr/main)에서 서핑 시설 안내를 확인했다.
- 곤지암: [공식 스키장 안내](https://www.konjiamresort.co.kr/ski/useInfo.dev)의 스키/보드 안내와 하단 주소를 대조했다. 홈페이지를 이 스키장 안내로 변경했다.
- 스카이라인 루지 부산: [공식 사이트](https://busan.skylineluge.kr/en/)에서 루지 시설과 홈페이지를 확인했다. 도로명 주소·좌표는 TourAPI 값을 유지하며 OFFICIAL 출처의 주소·좌표 검수 항목에는 포함하지 않았다.
- 정동진: [공식 시설 안내](https://www.railtrip.co.kr/kr/product_view.php?client_no=9)와 대조해 주소에 빠진 `강동면`을 보완하고, 통합 홈페이지를 시설별 안내 링크로 변경했다.
- 플라이스테이션: [공식 체험 안내](https://flystation.kr/usage/usage_020100.html)에서 종목과 주소를 대조했다. 접근 가능한 HTTPS 체험 안내로 홈페이지를 변경했다. 같은 페이지 내 체험 시간과 하단 운영시간도 차이가 있어 시간을 따로 저장하지 않았다.

소개는 확인한 시설 사실을 바탕으로 짧게 직접 작성했다. 원본 TourAPI 수집 출처는 미검수 상태로 보존하고, 별도의 OFFICIAL 출처에 실제 확인한 항목과 날짜만 기록했다. `verified_at`/`reviewed_at`은 날짜 단위 확인이라 2026-11-16 00:00:00으로 기록한다. `verifier_id`는 비어 있으며 팀 운영자 계정의 승인 이력이라고 주장하지 않는다.

기존 이름·주소·홈페이지가 수집 당시 값과 같은 미검수 DRAFT만 처리한다. 이미 공개했거나 다른 사람이 수정·검수한 장소는 건너뛴다. 한 트랜잭션으로 반영하며 재실행은 출처를 중복 추가하지 않는다. 로컬 실행에서 첫 회 5곳, 두 번째 0곳을 확인했다. 기존 가상 장소 6곳은 유지한다.

이 공개 직후에는 사진, 정밀 좌표의 독립 검증, 시즌·실내외 필터 값, 현재 운영 상태·요금이 미확인이었다. 시즌·실내외 후속 대조 결과는 아래와 같다.

## 초기 장소의 실내외·시즌 후속 대조

`scripts/review-initial-place-filters.sql`을 로컬에서 별도로 실행한다. 수집 시 기본값을 바꾸거나 Flyway에 장소 데이터를 넣지 않는다. 시즌은 현재 영업 여부나 방문일 예약 가능 여부가 아닌 종목별 탐색 분류다. 월별 기간을 변환할 때 봄 3~5월, 여름 6~8월, 가을 9~11월, 겨울 12~2월을 사용했다.

- 웨이브파크 **서핑**: 실외, 봄·여름·가을. [서핑 시설 안내](https://www.wavepark.co.kr/surf)를 근거로 실외로 분류하고, [2026 운영기간 4월 25일~10월 31일](https://www.wavepark.co.kr/operatinghours)을 세 계절에 대응시켰다. [10월 31일 서프존 시즌 종료](https://www.wavepark.co.kr/board/notice?act=view/detail/95)도 확인했다. 겨울 운영이나 2027 일정은 추정하지 않았다. 다음 시즌 공지 시 재검토해야 한다.
- 곤지암 **스키와 스노보드 각각**: 실외, 겨울. [공식 겨울 스키장·설원·슬로프 및 스키/보드 안내](https://m.konjiamresort.co.kr/ski/skiGuide.dev)를 근거로 분류했다. 정확한 개장·폐장일이나 봄 연장 운영은 별도로 확인하지 않았다. 리조트의 여름 시설은 이 두 종목의 시즌에 적용하지 않는다.
- 부산 **루지**: 실외, 봄·여름·가을·겨울. [공식 다운힐 트랙·스카이라이드 안내](https://busan.skylineluge.kr/en/)로 실외로 분류했다. [공식 연중 멤버십과 매일 루지 이용 혜택](https://busan.skylineluge.kr/en/membership/)을 근거로 사계절로 분류했다. 날씨나 임시 휴장 예외까지 보장하는 값은 아니다.
- 정동진 **레일바이크**: 실외, 봄·여름·가을·겨울. [공식 바다 노선 및 3~4월·5~10월·11~2월 운행표](https://www.railtrip.co.kr/kr/product_view.php?client_no=9)를 근거로 분류했다. 일별 운행은 별도 확인 대상이다.
- 플라이스테이션 **실내 스카이다이빙**: 실내, **시즌 미확인**. [공식 실내 체험 설명](https://flystation.kr/intro/intro_030100.html)은 확인했지만 사계절/연중 운영을 직접 명시한 근거는 확보하지 못했다. 실내라는 이유만으로 사계절을 채우지 않았다. 실내 필터에서는 보이지만 시즌을 추가하면 제외된다.

실내외는 공식 시설·활동 설명을 서비스 코드 `INDOOR`/`OUTDOOR`로 사람이 분류한 값이며, 외부 API의 구조화된 실내외 코드라고 주장하지 않는다. 기존 실내외 값이나 시즌 행이 하나라도 있는 종목은 전체 검토를 건너뛰어 다른 작업자의 분류를 덮어쓰지 않는다. 외부 콘텐츠 ID와 연결된 종목만 대상으로 삼으므로 가상 장소 6곳은 변경하지 않는다.

실내외와 시즌의 출처는 구분해 OFFICIAL 출처로 추가하며, 종목명·판단 근거·한계는 내부 메모에 남긴다. 정확한 시각을 검수한 기록이 아니므로 확인일은 날짜 단위로 기록한다. 실제 반영은 6개 종목의 실내외와 13개 시즌 행이다. 재실행은 0개 종목을 처리한다.
